Exhibitors.ai Design System

Cross-platform design language for web app, mobile app (React Native), and marketing site. Source of truth for all visual and interaction decisions.

Exhibitors.ai's visual language projects confident calm in the middle of chaos. Trade shows are loud, overwhelming, and relentless. The warm cream palette, generous whitespace, and serif headings ground users with the steady presence of a plan already in motion. This is a tool built by people who understand what it feels like to come home with 200 contacts and no system. Teal sits at the intersection of composure and conviction. Steady enough to trust with your pipeline, sharp enough to feel like a competitive edge. Inter keeps the interface precise when pressure is real, and the four-accent classification system turns raw contact lists into a clean, considered editorial layout. Restrained shadows and purposeful spacing are not decorative. They say: we will be the calm part of your post-show week.

Font Pairing Rules

Serif (Source Serif 4): All headings, display text, contact/company names on cards, pull quotes, metric values, brand wordmark. Conveys editorial authority.

Sans (Inter): All body text, form labels, button text, navigation items, table cells, badges, metadata. Conveys functional clarity.

Rule of thumb: If the text establishes hierarchy or identity, use serif. If the text is actionable or informational, use sans.

Interaction Patterns

How the same actions adapt across web and mobile platforms.

Navigation

Web ↔ Mobile

Web: 220px sidebar with section labels, hover highlights, active state.
Mobile: Bottom tab bar (4 tabs max). Secondary nav via stack navigation with back arrow. No hamburger menu.

Data Tables ↔ List Cards

Web ↔ Mobile

Web: Full data table with sortable columns, row hover, batch selection.
Mobile: Stacked list cards showing name + company + badge. Tap to expand detail. Swipe for quick actions (edit, delete).

Modals & Overlays

Web ↔ Mobile

Web: Centered modal (max 560px wide) with overlay. Slide-out panel (420px) from right for detail views.
Mobile: Bottom sheet (drag to dismiss) for options. Full-screen modal for forms. No centered modals.

Hover ↔ Touch

Web ↔ Mobile

Web: Hover reveals secondary actions, shows tooltips, highlights interactive elements.
Mobile: Long-press for context menu. Visible action buttons (no hidden hover states). Haptic feedback on destructive actions.

Forms & Input

Web ↔ Mobile

Web: 40px input height, focus ring, inline validation below field.
Mobile: 44pt minimum touch target. Keyboard-appropriate input types (email, tel, number). Validation on blur, not on keystroke.

Destructive Actions

Both Platforms

Always require confirmation. Web: centered modal with "Cancel" (outline) and "Delete" (danger) buttons. Mobile: bottom sheet confirmation with red destructive button. Never use swipe-to-delete without undo.

Loading States

Both Platforms

Use skeleton screens for initial page loads (not spinners). Show inline spinners only for actions (button loading state). Progress bars for multi-step operations (import, generation). Skeleton shimmer animation: 1.5s ease infinite.

Empty States

Both Platforms

Every empty view has: a headline (serif, 18px), a description (sans, 13px, muted), and a primary action button. No blank screens. Use warm, editorial tone — "Your first list starts here" not "No data found."

Transitions

Both Platforms

Micro: 0.15s ease — hover states, toggle, button press.
Base: 0.2s ease — dropdown open, tooltip appear.
Slow: 0.25s ease — slide-out panel, accordion expand.
Panel: 0.3s ease — modal overlay, page transition.
